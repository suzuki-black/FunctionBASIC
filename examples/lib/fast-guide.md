# FAST library — 適用ガイドと性能モデル（実測ベース）

`lib/fast.msxb` は「速度が要る所だけ」使う **opt-in の逃げ道レイヤ**です。
FunctionBASIC の既定は **透明で読める MSX-BASIC**。FAST はその上に載る、
1フレーム分の重い処理を丸ごと ASM に畳むバッチ・プリミティブ集です。

このガイドは「どんなゲームが実用速度で作れるか」を **turbo R 実機（MSXPen turbo R運用）
の実測**から数値化し、FAST をいつ使う／使わないかの指針を示します。

---

## 1. 前提：2つの拘束

ゲームのfpsは、順に効く2つの拘束で決まります。

1. **VDP のハード上限（CPU 無関係）**
   - スプライト：**同時 32 枚 / 横1ラインに 8 枚**（8×8 でも 16×16 でも枚数制限は同じ）
   - BG タイル：SCREEN 1 で **パターン 256 種 / 画面 768 セル**

2. **1フレームの CPU 予算（ここが FAST で動く）**
   - **インタプリタ BASIC は turbo R でも予算が極小**。中核ループだけで **~24fps が上限**、
     オブジェクトを足すほど低下。**60fps はインタプリタでは不可**（＝コンパイラ領域）。
   - **FAST は per-object の「描画・移動・当たり」を ASM バッチ化**し、1体あたりのコストを
     大きく下げる。ただし **BASIC のままの base loop が fps 天井**を決める。

---

## 2. 実測（turbo R・3ジャンル典型）

| ジャンル | 構成 | 純BASIC | FAST適用 |
|---|---|---|---|
| **STG（インベーダー型）** | 敵55（BGキャラ・lockstep）+弾+砦 | 満載 ~5 / 減ると ~20 | 敵移動を丸ごとASM化で満載も改善 |
| **アクション（横スクロール）** | 敵6+弾4（スプライト）+重力+HWスクロール | 無操作 11-12 / **連射 6** | 無操作 12 / **連射 8**（弾×敵をASM一括） |
| **パズル（落ち物）** | 1ピース落下・低頻度更新 | **30-60** | 不要 |

読み取れた法則：

- **HW スクロール（turbo R `SET SCROLL`）≒ 0 コスト**（実測確認済み）。
- **FAST は per-object のバッチ処理を確実に軽くする**が、**base loop（入力・物理・当たり・
  弾/敵ロジック）が BASIC のままだと ~12fps 前後が天井**（アクション6体＋物理＋弾の場合）。
- **更新が低頻度なジャンル（パズル等）は純BASICで 30-60fps**。FAST はほぼ不要。

---

## 3. 性能モデル（1フレーム所要 ≒ 加算式）

```
frame_ms ≒ 30(基本ループ)
         + N_basic × 6      … ロジックがBASICな動く物（移動+当たり）
         + N_fast  × 1.5    … ロジックもFAST(ASM)な動く物（スプライトは32枚まで）
         + tiles_redraw_basic × 3   … 毎フレーム描き替えるBGタイル（VPOKE）
         + tiles_redraw_fast  × 0.4 … 同左を FAST_TILES/TILEGRID で
         + scroll( HWスクロール = 0 / SWスクロール = 描き替えタイル数ぶん )
         + sound( PSGレジスタ直書き ≒ 0 )
fps = 1000 / frame_ms
```

※ ms 係数は turbo R 実測からの概算。**相対関係**（発射で半減／FASTで per-object が軽い／
HWスクロールが 0 コスト）はどの機種でも成立。絶対値は CPU 速度に比例（MSX2/Z80 なら約半分）。

### 作れるゲーム像（数値化の結論）

| | 純BASIC | FASTライブラリ | (参考)コンパイル(べーしっ君等) |
|---|---|---|---|
| 動く物 | ~5 体 | **~26-32 体**（VDP 32枚が壁） | 制限=VDPのみ |
| fps | 15-24（少数）/ 低下大 | ~24-30（バッチ化した範囲） | 60 |
| 向くジャンル | パズル/ADV/ゆっくり迷路 | 少数精鋭アクション/固定画面STG/インベーダー型（HWスクロール可） | 何でも |
| 不向き | 動く物多数 | 32体超・弾幕・60fps必須 | — |

## 4. いつ FAST を使うか（判断ガイド）

- **毎フレーム多数のスプライトを更新する** → `FAST_SPRITES`（OAM一括）。枚数が多いほど効く。
- **敵群/編隊/星を一定方向に流す**（横/縦スクロール、リングラップ） → `FAST_DRIFT`（等速移動＋X/Y軸ラップ）。
- **弾/粒子を撃ちっぱなしで飛ばし、画面外で消す** → `FAST_STREAM`（activeだけ移動＋画面外で自動deactivate）。
- **弾×敵など「集合×集合」の当たりを毎フレームやる** → `FAST_COLLIDE`（発射で落ちる問題の特効薬）。
- **BGタイルを毎フレーム大量に描き替える**（編隊・スクロール背景の列供給・全面書換） →
  `FAST_TILES`（列挙）/ `FAST_TILEGRID`（生存マスク直走査・詰め替え不要）。
- **HWスクロールできる面** → `SET SCROLL`（turbo R）を素で使う。ほぼ 0 コスト。FAST不要。
- **更新が低頻度（パズル・ボード・ADV）** → **FAST 不要**。純BASICで高fps。
- **本気の 60fps／弾幕** → FAST では届かない。**全体をコンパイル**（べーしっ君等）が王道。

### 交差点：動かす対象が何体からFASTか（実測）

「動かす」系（`FAST_DRIFT`/`FAST_STREAM`）は固定オーバヘッド（毎フレームのVARPTR段取り）を
持つので、**対象が少ないと素のBASICに負ける**。turbo R(内蔵WebMSX)で同一処理を純BASICの
FORループ vs `FAST_DRIFT` で実測した交差点:

| 動かす体数 N | 純BASIC fps | FAST_DRIFT fps |
|---|---|---|
| 4  | **42**（BASIC勝ち） | 36 |
| 12 | 27 | **36**（FAST勝ち） |
| 32 | 15 | **35**（FAST圧勝） |

- **FASTはNにほぼ無関係でフラット**、**純BASICはNに線形で悪化**。交差点は **N≒7**。
- 判断ルール：**動かす対象がおおむね8体以上なら FAST_DRIFT/FAST_STREAM、7体以下は素のBASICが速い**。
  （自機1体などは当然BASIC。弾も数発ならBASIC、弾幕級に増えて初めて `FAST_STREAM` が効く。）

### アンチパターン
- **疎らに1つずつ動くもの**（インベーダーの1匹ずつ移動）に **タイル一括系（FAST_TILEGRID）を
  全消し全描きで使う** → チラつく＆的外れ。per-object が元々軽いのでバッチの旨みが無い。
  → その場合は「1匹ずつ消して即描く」を（必要なら移動エンジンごと）ASM化する。
- **1:1 の命令置換**（`FAST PUT SPRITE` のような）→ BASIC↔ASM の往復コストを毎回払うので逆効果。
  FAST の単位は常に「1フレーム分のバッチ」。

## 5. 収録プリミティブ

| 名前 | 役割 | 主に効くジャンル |
|---|---|---|
| `FAST_SPRITES(N)` | 全スプライト属性を OAM へ一括 | STG / アクション |
| `FAST_DRIFT(base,n,vx,vy,wrapx,wrapy)` | スプライト群を等速移動＋X/Y軸ごとリングラップ（0=ラップ無し） | 横/縦スクロール敵・編隊・星 |
| `FAST_STREAM(base,n,vx,vy,xmax,ymax,parky)` | activeな物だけ等速移動、画面外で自動deactivate＋退避（生存数を返す） | 弾幕・粒子 |
| `FAST_TILES(N)` | BGタイルN個を列/行/キャラ配列で一括 | 汎用（スクロール背景の列供給等） |
| `FAST_TILEGRID(rows,cols,pitchx)` | 生存マスクを直接走査してタイル格子を一括（詰め替え不要） | 敵編隊/タイルマップの面描画 |
| `FAST_COLLIDE(ns,ne)` | 全弾×全敵の AABB 当たりを1回のASMで解決（命中数を返す） | STG / アクション |

「描く（SPRITES/TILES/TILEGRID）・動かす（DRIFT/STREAM）・当てる（COLLIDE）」の3系統が
1フレーム分のバッチとして揃った。いずれも交差点 N≒8 以上で効く（§4）。

**設計の結論**：3ジャンルの共通項は「フレーム同期・入力・HWスクロール・スプライト/タイルの
一括描画・集合当たり」に収まり、**単一の `fast.msxb`（Core + FASTバッチ一族）で足りる**。
パズルはロジック主体で追加プリミティブ不要。ジャンル別ライブラリに割る必要は現時点で無い。

---

## 6. 使い方の骨子

各プリミティブは「呼ぶ前に %整数配列を用意 → 関数を1回呼ぶ」だけ。詳細な配列名・前提は
`lib/fast.msxb` の各関数ヘッダを参照。ASM は `EX DE,HL` / `SBC HL,rr` / `LDIR` 等を使うため、
FunctionBASIC の拡張 Z80 アセンブラ（`src/asm/z80asm.ts`）で組み上がる。
